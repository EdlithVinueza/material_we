🧠 Desarrollo conceptual▶

Las consultas a una API deben ejecutarse de forma asíncrona para mantener la interfaz disponible mientras llega la respuesta. Valida los datos JSON antes de mostrarlos y distingue carga, éxito, error de red y ausencia real de registros. La persistencia local permite conservar favoritos y consultar una copia de los datos cuando no hay conexión; indica cuándo se actualizaron para evitar interpretaciones equivocadas. Si integras un sensor o servicio inteligente, solicita el permiso al usar la función y ofrece una alternativa cuando se rechace. Mantén las credenciales fuera del código público.

💡 Ejemplo didáctico resuelto▶

Caso. Una aplicación ficticia de clima borra los pronósticos al iniciar una actualización. Cuando pierde la conexión, muestra la lista vacía y el mensaje «No hay alertas», aunque antes existían datos guardados.

Diagnóstico de falla. La interfaz confunde un fallo de red con la ausencia de registros y elimina información útil. La persona puede interpretar que no existen alertas cuando la consulta ni siquiera llegó a completarse.

Corrección técnica. Conserva la caché con la fecha de la última respuesta exitosa. Muestra «Sin conexión; mostrando datos guardados» y ofrece reintentar. Actualiza la copia local únicamente cuando recibas una respuesta válida del servicio.

🧭 Ejercicio guiado para el trabajo autónomo▶
  1. Comprueba la respuesta de la API y los estados de carga, éxito y error. Revisa también qué muestra la aplicación cuando la respuesta válida no contiene registros.
  2. Guarda los favoritos y los datos necesarios localmente. Cierra la aplicación, vuelve a abrirla y verifica qué información permanece disponible y cómo se identifica su actualización.
  3. Prueba sin conexión y revisa los permisos del servicio inteligente o sensor utilizado. Explica cómo se recupera la consulta y qué alternativa existe si se rechaza un permiso.
